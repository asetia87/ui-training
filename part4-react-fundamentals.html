A component is a function

A component takes inputs and returns a description of UI. Names start with a capital letter, and you use them like HTML tags.

A component is an ERB partial with typed locals, except it can also hold state and react to clicks.
JSX
you write TSX
<li className="row" onClick={open}>
  {p.name} <Badge n={p.rfis} />
</li>
compiles to JS
jsx("li", { className: "row", onClick: open,
  children: [p.name, jsx(Badge, { n: p.rfis })] })

JSX is just function calls

JSX is syntax sugar for creating plain objects describing elements. { } embeds any JS expression. Use className, not class.

Think of it as a type-checked template DSL that compiles to a tree builder, like a JSX version of Jbuilder for HTML.

You never touch the DOM. Change state, and React calls f() again.

UI = f(state)

You describe what the UI looks like for a given state. When state changes, React re-runs your function and updates the page to match.

Like a pure view: render(model) → HTML. You don't write "insert row 3"; you re-render from the model, and React works out the minimal changes.

Props are typed, read-only inputs

The parent passes data down as props. TypeScript checks every call site. A component must never modify its props; data flows one way, top to bottom.

Props are constructor args of an immutable value object: the parent owns them, the child only reads.
Component tree

Apps are trees of components

Each component renders others. Data travels down as props; changes travel up through callback props (coming soon).

State · useState
TSX
function Counter() {
  const [count, setCount] = useState<number>(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

Give a component memory

useState returns the current value and a setter. Calling the setter schedules a re-render; the next call of Counter() sees the new value.

State lives in React, keyed by the component's position in the tree, like a per-instance field the framework stores for you between calls.
What is a render?

A render = calling your function

Rendering is just React calling your component function. It must be pure: no fetches, no DOM edits. Only the commit step touches the real page.

Immutability
TSX TSX
// ✗ same array reference: React sees no change
projects.push(p);
setProjects(projects);

// ✓ new array: re-render
setProjects([...projects, p]);
setProject({ ...project, status: 'closed' });
setCount(c => c + 1);   // updater form

Replace state, don't mutate it

React compares old and new state by reference. Mutating in place keeps the same reference, so nothing updates. Use the updater form when the new value depends on the old one.

Treat state like a Java record or a frozen Ruby object: you build a modified copy, never edit the original.
Virtual DOM

Diff two trees, patch the minimum

React keeps the last element tree in memory (the "virtual DOM"), diffs it against the new one, and applies only the differences to the real DOM, because DOM work is the expensive part.

Like a schema migration tool diffing desired vs current schema and emitting only the needed ALTERs.

Run code after the render commits

An effect runs after React updates the DOM. The returned function is the cleanup, called before the next run and on unmount.

Like an ActiveRecord after_commit callback with a matching teardown, or a try-with-resources block tied to the component's lifetime.

Loading, error, data

Model all three states explicitly: loading (no data yet), error, and success. Each gets its own early return.

Same discipline as handling a nullable result and a failed HTTP call in a Java client. In real apps, libraries like TanStack Query wrap this pattern with caching.
Race conditions
TSX
useEffect(() => {
  const ctrl = new AbortController();
  fetch(`/api/projects/${id}`, { signal: ctrl.signal })
    .then(r => r.json())
    .then(setProject)
    .catch(e => { if (e.name !== 'AbortError') setError(e); });
  return () => ctrl.abort();   // id changed or unmounted
}, [id]);

Cancel stale requests

If the user clicks project 42 then 43 quickly, the slow 42 response could arrive last and win. Aborting in cleanup guarantees only the latest request updates state.

Lists & keys
TSX
<ul>
  {projects.map(p => (
    <li key={p.id}>{p.name}</li>   // stable, unique id
  ))}
</ul>

Render arrays with map + key

key tells React which item is which across renders, so it can move, insert or remove rows correctly instead of re-using the wrong DOM node.

A key is a primary key. Using the array index is like identifying rows by OFFSET: it breaks as soon as you insert or sort.
Why keys matter

Index keys mix up rows

With index keys, inserting at the top shifts every key, so local state like a checked box or typed text attaches to the wrong row. Real ids fix it.

Events
TSX
function Row({ p, onSelect }: {
  p: Project;
  onSelect: (id: number) => void;
}) {
  const handle = (e: React.MouseEvent<HTMLLIElement>) => {
    e.stopPropagation();
    onSelect(p.id);
  };
  return <li onClick={handle}>{p.name}</li>;
}

Handlers are props that take functions

Pass a function, don't call it: onClick={handle}, not onClick={handle()}. Event objects are typed, e.g. React.ChangeEvent<HTMLInputElement>.

Like registering a listener or a callback interface in Java, here passed as a plain prop.
Controlled forms
TSX TSX
const [name, setName] = useState('');
<input value={name}
  onChange={e => setName(e.target.value)} />
state: { name: "" }

State is the source of truth

A controlled input shows value from state and reports every keystroke via onChange. Type above: the state updates, and the input re-renders from it.

Like a form object (Rails form_with model:) that is updated on every keystroke instead of only on submit, so validation can run live.
Lifting state up

Shared state lives in the common parent

When two siblings need the same data, move the state to their closest common parent. Pass the value down as props and a setter callback down for changes.

Like moving a field from two services into the one service that coordinates them: one owner, others get read access and a command method.

function NewProjectForm({ onCreate }: {
  onCreate: (name: string) => void;
}) {
  const [name, setName] = useState('');
  const submit = (e: React.FormEvent) => {
    e.preventDefault();
    if (!name.trim()) return;
    onCreate(name.trim()); setName('');
  };
  return (<form onSubmit={submit}>
    <input value={name} onChange={e => setName(e.target.value)} />
    <button disabled={!name.trim()}>Add</button></form>);
}

NewProjectForm (controlled)

The form owns only its draft text. On submit it calls onCreate and clears itself; the list itself lives in the parent.

Lab · step 5
TSX
function App() {
  const [projects, setProjects] = useState<Project[] | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [selectedId, setSelectedId] = useState<number | null>(null);
  useEffect(() => { api.list().then(setProjects)
    .catch(e => setError(String(e))); }, []);
  if (error) return <p>Error: {error}</p>;
  if (!projects) return <p>Loading…</p>;
  const sel = projects.find(p => p.id === selectedId);
  if (sel) return <ProjectDetail project={sel} onBack={() => setSelectedId(null)} />;
  return (<>
    <NewProjectForm onCreate={name => setProjects(ps => [...ps!,
      { id: Date.now(), name, status: 'open', rfis: 0 }])} />
    <ProjectList projects={projects} onSelect={setSelectedId} /></>);
}

App: state lifted, data fetched

App owns the shared state (the list and the selection), handles loading and error, and wires children together with props and callbacks.

src/App.tsx TSX
import { useEffect, useState, type FormEvent } from 'react';

export interface Project {
  id: number;
  name: string;
  status: 'open' | 'closed';
  rfis: number;
}

const db: Project[] = [
  { id: 1, name: 'Riverside Tower', status: 'open', rfis: 12 },
  { id: 2, name: 'Harbor Clinic', status: 'closed', rfis: 3 },
];
const delay = (ms: number) => new Promise(r => setTimeout(r, ms));
const api = { list: (): Promise<Project[]> => delay(600).then(() => [...db]) };

function ProjectList({ projects, onSelect }: {
  projects: Project[];
  onSelect: (id: number) => void;
}) {
  return (
    <ul>
      {projects.map(p => (
        <li key={p.id} onClick={() => onSelect(p.id)} style={{ cursor: 'pointer' }}>
          {p.name} <small>({p.status})</small>
        </li>
      ))}
    </ul>
  );
}

function ProjectDetail({ project, onBack }: { project: Project; onBack: () => void }) {
  return (
    <section>
      <button onClick={onBack}>← Back</button>
      <h2>{project.name}</h2>
      <p>{project.rfis} open RFIs · {project.status}</p>
    </section>
  );
}

function NewProjectForm({ onCreate }: { onCreate: (name: string) => void }) {
  const [name, setName] = useState('');
  const submit = (e: FormEvent) => {
    e.preventDefault();
    if (!name.trim()) return;
    onCreate(name.trim());
    setName('');
  };
  return (
    <form onSubmit={submit}>
      <input value={name} onChange={e => setName(e.target.value)} placeholder="New project" />
      <button disabled={!name.trim()}>Add</button>
    </form>
  );
}

export default function App() {
  const [projects, setProjects] = useState<Project[] | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [selectedId, setSelectedId] = useState<number | null>(null);

  useEffect(() => {
    api.list().then(setProjects).catch(e => setError(String(e)));
  }, []);

  if (error) return <p>Error: {error}</p>;
  if (!projects) return <p>Loading…</p>;

  const selected = projects.find(p => p.id === selectedId);
  if (selected) return <ProjectDetail project={selected} onBack={() => setSelectedId(null)} />;

  return (
    <main style={{ fontFamily: 'system-ui', padding: 16 }}>
      <h1>Projects ({projects.length})</h1>
      <NewProjectForm
        onCreate={name =>
          setProjects(ps => [...(ps ?? []), { id: Date.now(), name, status: 'open', rfis: 0 }])
        }
      />
      <ProjectList projects={projects} onSelect={setSelectedId} />
    </main>
  );
}

Recap

React on one card

  • Components are functions returning JSX; JSX compiles to element objects. Props are typed, read-only inputs.
  • UI = f(state). useState setters schedule a render (calling your function); React diffs trees and patches only changes.
  • Replace state, never mutate: spread copies and the updater form.
  • useEffect for side effects: deps array, cleanup, AbortController; handle loading/error/data.
  • Lists need stable keys; handlers are function props; controlled inputs; lift state up to the common parent.
